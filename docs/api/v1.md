# GoreeCloud Network API v1

**Lifecycle:** Development

The v1 API currently exposes Development control-plane discovery, persistence metadata, an Identity-backed administrative authentication boundary, and decision primitives. It is not a production administration or tunnel-control API.

## Implemented Development endpoints

- `GET /healthz` — process health.
- `GET /api/v1/status` — product version, lifecycle, and surface implementation state.
- `GET /api/v1/overview` — current device/resource/policy counts plus policy, persistence, schema, revision, migration, integrity, and authentication state.
- `GET /api/v1/storage` — read-only Development store metadata. It never returns state-file contents or secrets.
- `GET /api/v1/authentication` — read-only GoreeCloud Identity consumer-boundary status; never returns client credentials or bearer tokens.
- `GET /api/v1/admin/session` — protected Development probe. Requires a bearer token authenticated through the configured GoreeCloud Identity OAuth token-introspection boundary and the required Network administrator scope.
- `GET /api/v1/devices` — read-only device inventory restored from the Development store during normal server startup.
- `POST /api/v1/access/evaluate` — decision-only access evaluation. Requests require `principalId` and `resourceId`; `deviceId` is optional. The evaluator permits access only when an explicit loaded allow policy matches and otherwise denies by default.
- `GET /api/v1/platform-systems` — declared Integral Platform System implementation/evidence states.
- `GET /api/v1/capabilities` — machine-readable capability truth table.

## GoreeCloud Identity boundary

Network does not issue identities or implement a parallel sign-in system. The Development server can consume GoreeCloud Identity through OAuth 2.0 token introspection using runtime configuration:

- `GOREECLOUD_NETWORK_IDENTITY_INTROSPECTION_URL`
- `GOREECLOUD_NETWORK_IDENTITY_CLIENT_ID`
- `GOREECLOUD_NETWORK_IDENTITY_CLIENT_SECRET`
- optional `GOREECLOUD_NETWORK_IDENTITY_EXPECTED_ISSUER`
- optional `GOREECLOUD_NETWORK_IDENTITY_EXPECTED_AUDIENCE`
- `GOREECLOUD_NETWORK_IDENTITY_ADMIN_SCOPE` (defaults to `goreecloud.network.admin`)

The introspection URL, client ID, and client secret must be configured together. Partial configuration fails server startup. Non-loopback introspection URLs must use HTTPS. The client secret is not emitted by API/status surfaces.

When no Identity runtime is configured, the authentication boundary remains fail-closed and `/api/v1/admin/session` cannot authorize an administrator. When configured, successful introspection still does not establish production SSO acceptance by itself.

No mutating administrative endpoint is exposed in this milestone.

## Persistence behavior

Normal Development server startup uses a revisioned schema-v1 JSON state envelope at `var/network-state.json`, configurable through `GOREECLOUD_NETWORK_DATA_FILE`. It remains a single-process Development store, not production database/HA/recovery infrastructure.

## Important boundaries

`POST /api/v1/access/evaluate` does **not** enforce packet flow or tunnel reachability. It returns `enforcement: decision_only` until a verified network enforcement point consumes the decision.

GoreeCloud Identity authentication does not equal Privacy Shield authorization, Wardveil trust, Network access-policy approval, or packet-path enforcement. Device enrollment/key issuance, mutating policy/resource administration, tunnel lifecycle, private routing, relay, obfuscation, posture enforcement, remaining Platform System integrations, production deployment, and Stable qualification remain incomplete.
